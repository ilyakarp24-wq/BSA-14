### Сценарий 1: Передача заказа из магазина в систему доставки (Поток 1)
**Тип:** Use Case (UC)  
**Акторы:** ИТ-система магазина (Primary), Система доставки (Secondary)  
**Предусловие:** В системе магазина создан новый заказ с доставкой.  
**Основной сценарий:**
1. ИТ-система магазина формирует сообщение с данными заказа (JSON/XML).
2. ИТ-система магазина отправляет запрос в API Системы доставки.
3. Система доставки валидирует данные (проверка обязательных полей, наличие адреса в справочнике).
4. Система доставки сохраняет заказ в статусе "Новый" и возвращает код успеха (200 OK) с внутренним ID заказа.
**Альтернативный сценарий:** 
3а. Данные не прошли валидацию. Система доставки возвращает ошибку (400 Bad Request) с описанием причины. Заказ не создается.  
**Постусловие:** Заказ отображается в ленте свободных заказов для курьеров.

### Сценарий 2: Обновление статуса заказа курьером (Поток 3)
**Тип:** Use Case (UC)  
**Акторы:** Мобильное приложение курьера (Primary), Система доставки (Secondary)  
**Предусловие:** Курьер авторизован в приложении и выбрал заказ.  
**Основной сценарий:**
1. Курьер нажимает кнопку изменения статуса (например, "Забрал заказ") в мобильном приложении.
2. Приложение отправляет запрос на сервер Системы доставки с параметрами: OrderId, CourierId, Status, Timestamp.
3. Система доставки проверяет, что заказ закреплен за данным курьером и переход статуса допустим по бизнес-логике.
4. Система доставки обновляет статус заказа в БД и возвращает подтверждение.
5. Система доставки инициирует Поток 5 (если статус "Доставлен").  
**Постусловие:** Статус заказа обновлен, диспетчер и клиент видят актуальную информацию.

### Сценарий 3: Передача данных о доставке в бухгалтерию (Поток 5)
**Тип:** Use Case (UC)  
**Акторы:** Система доставки (Primary), Бухгалтерская система (Secondary)  
**Предусловие:** Заказ переведен в статус "Доставлен".  
**Основной сценарий:**
1. Система доставки формирует сообщение `DeliveryConfirmation`.
2. Система доставки отправляет сообщение в Бухгалтерскую систему (через шину сообщений или API).
3. Бухгалтерская система принимает сообщение, валидирует его и ставит в очередь на расчет ЗП курьера.
4. Бухгалтерская система возвращает подтверждение получения (ACK).  
**Постусловие:** Данные о доставке зарегистрированы в бухгалтерской системе для последующего расчета.
